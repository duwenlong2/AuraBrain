# 框架调研笔记：Agent 技术栈真实情况

> 调研时间：2026-07-31
> 用途：第一篇博客（为什么选 Mastra）的素材。所有结论来自官方文档/官方仓库，标注了来源。

## 一、LangGraph（LangChain 公司）

**官方定位**：Low-level orchestration framework for building stateful agents（低层编排框架，用于构建有状态 agent）

来源：github.com/langchain-ai/langgraph + docs.langchain.com

- 语言：Python 为主，另有 LangGraph.js（TS 版）
- Star：38.5k
- 核心抽象：**图（StateGraph）**，节点（node）+ 边（edge），编译后运行
- 设计灵感：Google Pregel、Apache Beam，接口受 NetworkX 启发
- 核心能力：
  - durable execution（持久执行，失败后从断点恢复）
  - human-in-the-loop（interrupts 中断机制）
  - 内存：短期工作记忆 + 长期跨会话记忆
  - 可观测性靠 LangSmith（需接 LangChain 平台）
- 关键特征：**极低层（very low-level）**，只专注 agent 编排，不抽象 prompt 和架构
- 强项：确定性步骤和 LLM agentic 步骤可以在同一张图里混合

**认知修正**：LangGraph 不是"开箱即用的 agent 框架"，它是底层编排运行时。要快速做 agent，官方推荐用更高层的 Deep Agents / LangChain agents。

## 二、LangChain

**官方定位**：agent 框架，提供模型、工具、agent loop 的抽象和集成

来源：docs.langchain.com

- 语言：Python 为主（有 JS/TS）
- 定位：**框架层**（agent framework），比 LangGraph 高一层
- 生态划分（官方）：
  - LangChain = agent 框架（抽象 + 集成）
  - LangGraph = 编排运行时（持久执行、流式、human-in-the-loop）
  - LangSmith = 平台（tracing、评估、prompt、部署）
  - Deep Agents = 高层 agent harness（规划、子代理、文件系统）

**认知修正**：LangChain 和 LangGraph 是两个不同层级的东西，一个是框架一个是运行时，常被混为一谈。

---

## 三、OpenClaw

**官方定位**：Personal AI Assistant，自托管网关（self-hosted gateway）

来源：github.com/openclaw/openclaw + docs.openclaw.ai

- 语言：TypeScript（Node 22+）
- Star：**384.6k**（远超其他框架）
- 组织：OpenClaw Foundation（非盈利），MIT
- 核心：**Gateway 控制平面**，连接 25+ 聊天 App（WhatsApp、Telegram、Slack、Discord、Signal、iMessage 等）到 AI agent
- 面向人群：开发者/重度用户，想要"随时可发消息的个人 AI 助手"，自托管数据
- 能力：多渠道、多 agent 路由、技能（skills）、定时任务、移动端 node、语音
- 还有 Companion Apps（macOS/iOS/Android 节点）

**认知修正（重要）**：OpenClaw **不是 Agent 开发框架**（不像 Mastra/LangGraph 那样给你 API 构建 agent），它更像一个"AI 助手的运行环境 + 多渠道接入层"。定位和 Mastra 完全不同，之前把它和 LangGraph 并列是错误的。

## 四、AutoGen（微软）

**官方定位**：多 agent AI 应用框架，可自主或与人类协作

来源：github.com/microsoft/autogen

- 语言：Python（+ .NET 跨语言支持）
- Star：60.1k
- ⚠️ **当前状态：Maintenance Mode（维护模式）**
  - 不再接受新功能
  - 微软官方建议新项目用 **Microsoft Agent Framework（MAF）**
- 分层设计：
  - Core API：消息传递、事件驱动 agent、分布式运行时
  - AgentChat API：简化的、偏 opinionated 的 API（快速原型）
  - Extensions API：LLM 客户端、代码执行等扩展
- 工具：AutoGen Studio（no-code GUI）、AutoGen Bench（评估）
- 代表项目：Magentic-One（多 agent 团队）
- MAF：企业级继任者，支持 A2A 和 MCP

**认知修正（重要）**：AutoGen 已进入维护模式，新项目官方推荐用 MAF。选型时 AutoGen 已经不是活跃选项。

## 五、Mastra

**官方定位**：用 TypeScript 构建 AI 应用和自主 AI 系统的开源框架

来源：mastra.ai/docs + 本仓库源码

- 语言：TypeScript 原生
- 核心抽象：**Agent 和 Workflow 是两个一等公民**
- Batteries-included：记忆、存储、可观测性、MCP、多 agent、信号、guardrails 全内置
- 有 Mastra Studio（可视化调试）、CLI、官方课程
- 部署：开源 + 可选托管平台

## 七、选型结论（初稿）

1. **OpenClaw 排除**：它是 AI 助手运行环境，不是开发框架，和"我要用框架构建 agent"诉求不符。
2. **AutoGen 排除**：已维护模式，微软自己都在推 MAF。
3. **LangGraph/LangChain**：强在生态和招聘量，但：
   - Python 为主（用户技术栈非 Python）
   - LangGraph 是低层运行时，构建复杂 agent 需要搭配 LangChain + LangSmith 全家桶
   - 可观测性、部署强依赖 LangSmith（商业平台）
4. **Mastra**：
   - TypeScript 原生，与用户技术栈匹配
   - Agent + Workflow 双一等公民，一个框架覆盖两种范式
   - 可观测性、记忆、存储全内置，不依赖商业平台
   - 开源 + 自托管友好（符合"云端方案整体开源"的诉求）

> 注意：以上是调研初稿，LangChain/Mastra 的 star、生态细节还需进一步核实。
